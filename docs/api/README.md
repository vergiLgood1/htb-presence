# HTB API reference (community)

`api_collection.json` is a copy of the community Postman collection
**HTB Api Docs (v4)** — the broadest public list of the internal v4 endpoints this
project relies on. Upstream:
<https://go.postman.co/collection/58571442-7cc865dd-80dc-42ea-a8fd-d18f15b113ac>
(by [Propolisa/htb-api-docs](https://github.com/Propolisa/htb-api-docs)).

It is reference material only. Nothing here is generated by this project and none of it
is load-bearing at runtime.

## What was changed before committing

- The collection-level **`auth` block was removed**. It carried a real Bearer token
  belonging to the collection author (expired 2023-08-07). Never commit credentials,
  even dead ones — see `AGENTS.md`.
- The **84 saved example responses were removed** to keep the repository small
  (3.7 MB → 77 KB). Fetch them again when a response shape is in question; that is
  where the shapes documented below come from.
- The pristine download is kept out of git as `api_collection.raw.json`
  (ignored by `.gitignore`) and still holds the examples and the old token.

Rebuild either variant from the pristine file:

```bash
cd docs/api
jq 'del(.auth), walk(if type == "object" then del(.response) else . end)' \
  api_collection.raw.json > api_collection.json    # slim, sanitized (committed)
jq 'del(.auth)' api_collection.raw.json > /tmp/full.json   # full, sanitized
```

## Caveats worth knowing before trusting it

- **The data predates the current API.** The collection's `{{API}}` variable points at
  `https://www.hackthebox.com/api/v4`, which **no longer serves the API**: every v4 path
  answers 404 there (rechecked 2026-09-28). The API now lives on
  `https://labs.hackthebox.com/api/v4`. Treat paths as useful, hosts as stale.
- **There is no endpoint for a spawned challenge instance.** `/challenge/list` lists
  challenges, not the one being worked on, and `/challenge/active` — which this project
  probes — does not exist on either host or in v5. If HTB adds one, it will have to be
  found in the browser's network tab, not guessed.
- **`/user/connection/status` is the documented VPN endpoint.** Two shapes are recorded:

  ```json
  {"status": "1", "connection": {"name": "Propolis", "ip4": "10.10.14.12", "down": "0", "up": "0.01"}}
  {"status": "0", "connection": "not connected"}
  ```

  The second one is why `parseConnectionObject` in `internal/htb` classifies the
  `connection` field instead of decoding it into a struct: as a string it would fail to
  unmarshal, and the API's authoritative "not connected" answer would be thrown away.
- **`/machine/active` already returns `name` and `avatar`**, while `os`,
  `difficultyText`, `authUserInUserOwns` and `authUserInRootOwns` come from
  `/machine/profile/{id}`. The example for that profile only carries a numeric
  `difficulty`, so `difficultyText` is worth checking on the first live run.
